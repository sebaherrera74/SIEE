Mi primer proyecto con FPGA: PWM con una Arty Z7-10

SIEE Lab · FPGA · VHDL · Vivado · Experimentación

FPGA Arty Z7-10 VHDL Vivado PWM

La idea parecía fácil

Después de bastante tiempo trabajando con electrónica, decidí que era una buena idea meterme con FPGA.

Como suele ocurrir en estos casos, uno empieza pensando: "Bueno, tampoco debe ser tan complicado. Hago un contador, genero una señal PWM y listo."

Spoiler: no era tan simple.

El objetivo inicial era bastante modesto: generar una señal PWM, controlar el duty cycle mediante unos botones y finalmente comprobar que la señal apareciera en un pin físico de la placa.

Lo que no había calculado era que para conseguirlo iba a tener que aprender VHDL, simulación, síntesis, implementación, constraints, bitstreams, Vivado y, sobre todo, la diferencia entre "el código funciona" y "la FPGA hace lo que yo creo que le dije que hiciera".

Así que decidí hacer algo todavía más peligroso: documentar el aprendizaje mientras lo estaba aprendiendo.

La placa

El proyecto fue realizado utilizando una Arty Z7-10, basada en un dispositivo Zynq-7000.

Una de las primeras cosas que tuve que tener en cuenta fue el reloj de la placa. La Arty Z7 utiliza un reloj de 125 MHz.

Eso significa que cada ciclo de reloj dura: 

125 MHz → 8 ns por ciclo

Este dato parece bastante inocente hasta que uno empieza a hacer las cuentas para generar frecuencias más bajas.

Primera lección: si el reloj es de 125 MHz, las cuentas tienen que hacerse con 125 MHz.

Primer objetivo: generar PWM

El primer PWM fue diseñado para trabajar a 1 kHz.

La cantidad de ciclos de reloj necesarios para completar un período es: 

125.000.000 Hz / 1.000 Hz = 125.000 ciclos

Por lo tanto, el contador del PWM debía recorrer 125.000 ciclos de reloj para completar un período.

A partir de ese contador se compara su valor con el porcentaje de duty seleccionado.

La idea es sencilla: 

contador < límite del duty → PWM = 1
contador ≥ límite del duty → PWM = 0

Control del duty cycle

Una vez que el PWM básico funcionaba, agregué el control mediante botones.

El duty podía seleccionarse en pasos de 10 %:

Selección Duty
0 0 %
1 10 %
2 20 %
... ...
10 100 %

Un botón aumenta el duty y otro lo disminuye. Cuando se llega al máximo, el siguiente paso vuelve a cero.

También implementé detección de flanco para que mantener presionado un botón no produzca un cambio continuo de valores.

En esta primera versión todavía no implementé debounce. Eso queda como una mejora pendiente para una futura versión.

Antes de tocar la placa: simulación

Una de las cosas que aprendí durante este proyecto es que conviene no correr directamente hacia la placa cada vez que uno cambia una línea de VHDL.

Para eso está la simulación.

Preparé un testbench que genera el reloj y simula las pulsaciones de los botones.

El reloj utilizado en el testbench fue de: 

CLK_PERIOD = 8 ns

Esto permite representar correctamente el reloj real de 125 MHz de la Arty Z7.

Durante la simulación comprobé el cambio del duty y posteriormente el cambio entre las diferentes frecuencias.

Del simulador al hardware real

Una vez que la simulación parecía correcta llegó el momento de generar la síntesis, implementar el diseño y generar el bitstream para programar la FPGA.

Y ahí apareció una de las partes más interesantes del proyecto: que algo funcione en simulación no significa que automáticamente funcione en el mundo real.

Para sacar la señal PWM de la FPGA utilicé el primer pin del conector Pmod JA.

El PWM quedó asignado al pin FPGA: 

JA1 → Y18

La señal fue observada finalmente con un osciloscopio.

El problema de BTN2

En determinado momento el PWM funcionaba, la simulación funcionaba y prácticamente todo parecía estar bien.

Excepto una cosa.

El botón para cambiar la frecuencia no hacía absolutamente nada.

Naturalmente, la primera reacción fue sospechar del VHDL.

Después de revisar el código y darle unas cuantas vueltas al asunto, resultó que el problema estaba en otro lugar: había asignado incorrectamente el pin del botón en el archivo XDC.

El BTN2 de la Arty Z7-10 está conectado al pin: 

BTN2 → L20

Mientras que el pin que había utilizado anteriormente, M20, corresponde a otro recurso de la placa.

Conclusión: la FPGA estaba bien. El que necesitaba debugging era yo.

Agregar control de frecuencia

Una vez solucionado el problema del botón, agregué la posibilidad de seleccionar tres frecuencias diferentes:

Selección Frecuencia Período en ciclos
0 1 kHz 125.000
1 2 kHz 62.500
2 5 kHz 25.000

Las cuentas son directamente: 

1 kHz → 125 MHz / 1 kHz = 125.000
2 kHz → 125 MHz / 2 kHz = 62.500
5 kHz → 125 MHz / 5 kHz = 25.000

Con cada pulsación de BTN2 se cambia la frecuencia: 

1 kHz → 2 kHz → 5 kHz → 1 kHz

Finalmente comprobé las tres frecuencias directamente sobre el hardware y el funcionamiento fue correcto.

Mediciones con el osciloscopio

Una vez funcionando el sistema sobre la Arty Z7-10, medí la señal PWM con el osciloscopio.

Para la frecuencia de 1 kHz obtuve los siguientes resultados:

Duty seleccionado Duty medido Frecuencia
10 % 10,4 % 1,000 kHz
30 % 30,4 % 1,000 kHz
50 % 50,4 % 1,000 kHz
70 % 70,4 % 1,000 kHz
90 % 90,4 % 1,000 kHz

La pequeña diferencia entre el valor seleccionado y el medido forma parte de las tolerancias y de la forma en que el osciloscopio determina el duty cycle.

Además de estas mediciones, comprobé físicamente el cambio de frecuencia entre 1 kHz, 2 kHz y 5 kHz, verificando que las tres opciones funcionaran correctamente.

¿Qué aprendí?

Que aprender FPGA es bastante más que escribir unas líneas de VHDL.

En este proyecto tuve que empezar a entender cómo trabajan conjuntamente el reloj, los contadores, la lógica secuencial, la simulación, la síntesis, la implementación, los constraints y finalmente el hardware.

También aprendí que hay una diferencia importante entre programar un microcontrolador y diseñar lógica para una FPGA.

Y aprendí algo todavía más importante: cuando algo funciona en simulación pero no funciona en la placa, no necesariamente hay que mirar el código durante tres horas seguidas.

A veces el problema está en el pin.

Y sí... eso también forma parte de aprender.

Próximos pasos

Este proyecto es solamente el primer paso.

Algunas mejoras que quedan pendientes son:

  • Agregar debounce real para los botones.
  • Mostrar el duty y la frecuencia mediante algún display.
  • Mejorar la arquitectura del diseño.
  • Explorar más recursos de la Arty Z7.
  • Incorporar procesamiento utilizando la parte Zynq de la placa.

La idea de este laboratorio no es solamente mostrar el resultado final, sino documentar también el camino para llegar hasta él.
